## 二、必须优先修复的两个问题

### 1. SSR HTML 净化回退不安全

文件：`astro/src/lib/security.ts`。调用处包括 `astro/src/pages/posts/[slug].astro`、`astro/src/layouts/PostLayout.astro`。

当前将 `isomorphic-dompurify` 已初始化的实例当工厂调用，导致 SSR 净化器不可用，退回正则处理。已在本地复现畸形 `img` 标签保留事件属性，并在模拟文章 DOM 中执行测试标记。攻击前提是恶意内容进入可发布正文；没有向生产写入测试攻击内容。

实施：正确使用 DOMPurify 实例，删除不安全的正则净化回退。不可用时拒绝或返回安全内容，不返回原始 HTML。保留合法文章格式、标签和属性白名单。

测试先行：新增 Node 环境 SSR 回归测试（现有 Vitest 默认 jsdom，不能代替 SSR 覆盖），验证未闭合标签、事件属性、危险 URL 以及正常文章格式；同时运行既有浏览器环境净化测试。

### 2. TOTP 失败计数随事务回滚

文件：`pb_hooks/lib/admin_totp_security.js` 的 `totpVerify`；测试：`admin-auth/test/admin-totp-verify-rate.test.mjs`。

失败分支在事务内写计数和审计后直接抛出 `ApiError`，PocketBase 会一起回滚。已在正确模拟回滚的测试中复现连续 12 次错误码均进入计算，失败桶和失败审计均未保留；独立 PocketBase 空库验证了真实事务行为。前提是有效管理员第一因素令牌及已绑定动态码，不等于直接接管账号。

实施：事务内记录预期失败结果并正常返回，使失败计数与审计提交；事务结束后再返回对应 API 错误。存储、解密等意外错误仍应回滚并拒绝请求。锁定期间的拒绝审计也应保留。

测试先行：修正现有 `runInTransaction` 测试替身，使抛错时回滚桶、审计和状态；再修复实现。覆盖第 5 次失败触发锁定、锁定后不再计算动态码、正确验证码、重放拒绝、锁定到期和存储异常。

## 三、数据采集与接口

复用现有运行状态监控的“宿主机定时采集 → 内部接口 → 数据库快照 → 公开汇总”模式：

1. 参考 `scripts/monitor-host.sh`，新增独立雷池汇总采集器。生产 Python 为 3.6，如使用 Python，需保持兼容且不增加庞大依赖。
2. 雷池 PostgreSQL 只读查询，按最近 24 小时时间窗和两个允许域名过滤。先核实动作枚举、时间戳单位、站点映射和事件去重规则，不能凭列名猜测拦截含义。
3. 已发现可调查的表：`mgt_detect_log_basic`、`mgt_rule_detect_log_basic`、`mgt_statistics_agg`、`mgt_website`。尚未确认哪些表重叠、哪种 action 表示拦截，接手者必须完成验证。
4. 新增受内部密钥与可信来源限制的写入接口，参考 `pb_hooks/lib/monitor_lib.js`、`pb_hooks/monitor_api.pb.js`。校验请求大小、字段白名单、时间戳和计数范围；不把凭据传给浏览器。
5. 新增最小必要快照集合，默认禁止通用公开读写。只新增 `pb_migrations/*.js` 迁移，并提供 down 路径。可保留最后成功快照与最近采集状态，避免失败被误当作零事件。
6. 建议公开路由 `/api/public/protection`，后台路由 `/api/blog-admin/monitor/protection`，内部路由 `/api/internal/monitor/protection`。最终命名可服从现有风格；管理接口复用已验证的管理员鉴权。
7. 公开接口只返回明确选取的汇总字段，不能直接序列化数据库记录。页面访问仅读取快照，不查询全量雷池日志。建议每分钟采样，超过 5 分钟未成功则标为过期；失败原因公开端只给通用状态，后台给受控错误分类。

若不能确认雷池动作语义，就标记该统计未接入，不用检测数量冒充拦截数量。源数据保留不足 24 小时时也应说明统计覆盖限制。
