# 博客数据分析系统重设计

日期：2026-11-26
状态：设计方向已确认，独立审查修正后待书面复核
范围：公开访问统计、后台统计与数据洞察；不包含运维监控改版

## 1. 目标与已确认决策

本设计同时服务读者与作者：公开页呈现站点热度，后台提供可信的趋势、对比、全维度下钻和导出。不是单纯更换皮肤，也不是引入一套新的访问追踪系统。

已确认：

1. 采用渐进增强方案：保留 PocketBase 采集，新增匿名日汇总与规范化分析接口。
2. 采用“总览 → 维度详情”的信息组织方式。
3. 视觉以科技感数据可视化为方向，延续深空蓝灰、冷青强调、精细刻度和轨道线，不使用满屏霓虹与装饰性球体。
4. 全球足迹以真实 2D 地图为主，3D 地球为按需增强。
5. 支持 7 / 30 / 90 天完整交叉筛选、上周期对比、文章／来源／地区／设备下钻和聚合数据导出。
6. 原始访问事件最多保留 90 个自然日；匿名日汇总长期保留。一年及全部历史只支持汇总趋势，不承诺维度下钻。
7. 不引入跨天访客标识、实时在线追踪、会话追踪、UTM 或外部 OLAP 平台。

## 2. 现状与必须先修复的问题

现有公开 `/stats`、`/admin/stats` 和 `/admin/insights` 共用部分接口，但页面入口、筛选与指标命名不统一。当前聚合集中在 PocketBase JSVM hook；不存在可假设的 Astro API 聚合层。

| 现状 | 证据与影响 | 设计要求 |
| --- | --- | --- |
| “最近 90 天”实际回落为 30 天 | `pb_hooks/lib/stats_lib.js:393` 只识别 7d；前端仍提供 90d | 接口白名单、响应范围与 UI 必须一致 |
| “总访问量”其实是窗口内浏览量 | `stats_lib.js:414-422` 有 `created >= from` | 显示“近 N 天浏览量” |
| “独立访客（30天）”并非跨天去重 | `stats_lib.js:126-128` 的 visitor hash 按日轮换 | 改为“访客·日”，提供定义 |
| 平均每日除以有访问的天数 | `InsightsDashboard.tsx:192-194`；daily 不补零 | 完整自然日补零，按窗口天数计算 |
| 公开趋势图交互和无障碍语义不足 | `StatsDashboard.tsx:154-173` | 图表提供表格、键盘操作和减少动态效果支持 |
| 地理区块无数据时直接消失 | `StatsDashboard.tsx:210` | 保留区块，显示无数据、未配置或失败状态 |
| `geo.regions` 对匿名请求包含城市字段 | `stats_lib.js:461-481` | 公开响应不含城市；地区详情仅管理员可用 |
| 两套文章阅读口径容易混淆 | `posts.views` 累计去重；page_views 是窗口事件 | 分开命名和解释，禁止强行加总校验 |
| 公开页错误后无重试 | `StatsDashboard.tsx:62-68` | 每个数据模块独立重试与降级 |

原始事件仍使用每日轮换的 HMAC 访客标识，不保存原始 IP。保留这一隐私边界，不为了实现“真正跨天 UV”改成长期标识。

## 3. 信息架构与路由

### 3.1 公开访问观测站 `/stats`

页面保留“访问统计”导航名称，主视觉采用“每一次到访，都有回响”的观测站叙事。

依次呈现：

1. 页面标题、真实更新时间、时间范围与数据口径入口。
2. 浏览量、访客·日、日均浏览、互动四项核心指标。
3. 浏览趋势，支持当前周期与上周期对比。
4. 全球足迹：地图、国家排行与 2D / 3D 切换。
5. 热门内容与访问来源摘要。
6. 隐私与统计口径说明。

公开页提供 7 / 30 / 90 天切换；一年／全部历史可以在趋势卡中查看，但不得显示无法支持的地理、来源、设备下钻入口。公开页不提供原始记录或任意筛选接口。

### 3.2 后台分析工作台 `/admin/insights`

将 `/admin/stats` 与 `/admin/insights` 合并为一个工作台。实施时保留旧入口并跳转，更新后台导航文案与指向，不保留两套独立取数看板。

工作台依次呈现：

1. 时间、文章、来源、地区、设备筛选，以及周期对比和导出。
2. 指标与环比。
3. 浏览量和访客·日趋势。
4. 内容、来源、地区、设备四个维度入口。
5. 当前上下文的数据表、排序、分页与导出。

筛选写入 URL 查询参数，支持刷新、前进、后退和复制链接。分享链接不绕过管理员认证，不包含任何敏感标识。

### 3.3 维度详情

文章、来源、国家／地区、设备分别使用同一详情框架：

- 对象标题、当前筛选与时间范围；
- 单对象趋势与对比；
- 关联维度分布；
- 可排序、分页的聚合明细；
- 返回上级时恢复原筛选与滚动上下文。

选择某篇文章后，可以继续筛选其来源、国家／地区与设备；选择来源后，也可继续查看文章与地区。所有组合使用同一个服务端过滤模型，不在浏览器自行拼合不同窗口的数据。

## 4. 视觉与交互设计

### 4.1 共同语言

沿用 `--sf-*` 设计令牌与 3–4px 的克制圆角，以表面色分层代替层层发光边框。图表使用冷青作为主色、灰蓝作为上一周期，语义色只表达成功、警告和错误。大数字使用等宽字体与 `tabular-nums`，正文保持可读字号，不把全部文字都做成小号大写英文。

科技感来自图表刻度、地图空间、轨迹与选中反馈，不通过持续闪烁、自动旋转、过量粒子或无意义动画制造。浅色主题与暗色主题都必须可读，图表颜色不能只在深色下成立。

### 4.2 全球足迹主舞台

桌面为横向主舞台：地图约占三分之二，国家／地区排行约占三分之一；窄屏依次排列地图与排行，避免固定 480px 高度挤压视口。

- 使用现有 `astro/public/world-zh.json` 与 ECharts 地图注册逻辑，不重新绘制虚假的世界轮廓。
- 2D 为默认模式；提供缩放、复位、热度图例和明确可聚焦的 2D / 3D 切换控件。
- 地图与国家排行使用同一选中状态。悬停、点击或键盘选择国家时，地图高亮并显示浏览量、访客·日及时间范围。
- 管理员可从选中地区进入详情；公开用户只看到国家级聚合和文章摘要。
- 3D 只在主动切换后动态加载；WebGL 不可用或初始化失败时回到可用 2D，不整页刷新。
- 保留现有地图数据的标准边界处理和前端 HK / TW / MO 到 CN 的聚合规则；接口、排行、地图与导出使用相同合并规则。
- 减少动态效果时禁用漂浮、粒子和地图过渡；低性能设备不自动进入 3D。

无 GeoIP、无匹配数据、接口失败是三种不同状态。地理区域必须保留，分别显示“地理数据未配置”“当前范围无地理数据”与可重试错误，不通过隐藏区块解决布局问题。

### 4.3 图表、表格与移动布局

ECharts 按需注册折线、面积、地图及必要交互组件，与地图共享渲染入口；不为另一套图表库增加依赖。SSR 不初始化浏览器图表实例，图表进入视口后加载。

- 折线图具有轴、单位、图例、时间范围和可聚焦数据点；触屏可读取同一详情。
- 每个图表都有等价表格或数据摘要，不在 `role="img"` 内放置大量无名称焦点。
- 任一当前周期或上一周期覆盖不足时，都不绘制缺失段的虚构零线、不给差值，显示“暂无可比历史”。
- 桌面工作台保持较高信息密度；手机端将组合筛选收进抽屉，保留已选条件摘要。
- 加载骨架按真实条件渲染分支保留空间；无需为了骨架“等高”伪造一个必然出现的地理模块。
- 所有非原生切换控件实现正确的 button / tab 语义、键盘操作、焦点可见和 `aria-controls`（如使用 tab）。

## 5. 数据模型与生命周期

### 5.1 保留原始事件，规范后续采集

继续使用 `page_views`，但新增迁移增加可空 `post_id`，供新事件直接记录已解析的已发布文章。`cascadeDelete` 必须为 false；文章删除后允许保留不可关联的历史 ID，不能级联删除原始统计。已有数据按规范化路径和当时可唯一解析的文章 slug 回填，不局限于当前 published 状态；已下架／已删除文章保留历史归属但归入“已下架文章”桶，不公开标题，无法解析的保持空值。另增加 `geo_status`（`resolved | unavailable | unresolved`）记录解析状态，使历史空地理可区分未配置与失败。

新采集先按现有规则校验完整路径，再规范为站内 pathname，移除 query 与 fragment；文章解析在规范化后进行。沿用现有路径长度限制、文章状态校验、来源 origin 化、限流与 DNT 客户端策略。不得把规范化误解为允许任意外部 URL 或管理路径。

原表不删除 visitor hash；新汇总表绝不保存 visitor hash、IP、完整 referrer、UA、秒级访问时间或城市。

### 5.2 匿名日汇总

新增以下三个集合：

**`analytics_daily`**

- `day`：Asia/Shanghai 自然日，唯一；
- `page_views`：当天 pageview 事件数；
- `visitor_days`：当天 distinct visitor hash 数；
- `geo_resolved_views`：成功解析地理的浏览数；
- `geo_unavailable_views`：GeoIP 未配置的浏览数；
- `geo_unresolved_views`：已配置但解析失败的浏览数；
- `finalized_at`：汇总时间。

每个已日结日都写一行，包括零浏览日，以区分“已确认零浏览”和“尚未日结”。

**`analytics_daily_dimensions`**

- `day`；
- `dimension`：仅允许 `post`、`path`、`referrer`、`country`、`region`、`device`；
- `value_key`：规范化 ID / origin / 国家代码 / 地区代码 / UA 分类；
- `page_views`；
- `visitor_days`；
- `finalized_at`。

`(day, dimension, value_key)` 唯一；region 的 key 统一为 `country + "|" + region_code`，中文省名与非中文小写代码在回填前用同一规范化函数处理，禁止同一地区生成两个 key。文章以 post ID 为 key；已下架／删除文章归入固定的 `unavailable` 桶。标题不是筛选键，也不在汇总表复制敏感信息。

`path` 维度只聚合无法归属到文章的页面事件；文章页只进 `post` 维度，不双计。无法解析到现有文章的 `/posts/<slug>` 路径统一进入 `post/unavailable`，不能泄入 path 列表。每天最多保留按浏览数排序的 100 个 path，余下进入 `other` 桶，避免随机路径使永久汇总无界增长。`post + path` 的合计等于总浏览量；不可见文章仍在 `post/unavailable` 内，不在 UI 内容排行暴露。

**`analytics_meta`（单例状态记录）**

- `timezone`：固定 `Asia/Shanghai`；
- `source_min_day`：全局可核验的最早原始数据日期；
- `last_finalized_day`：连续成功日结的最后日期；
- `updated_at`：状态更新时间。

日结事务同时写当日行、维度行和推进水位。水位不得跨过失败日；缺失日在接口 `coverage.missingDays` 明列，不按零值补齐。

互动另按 reactions / comments 的当前有效记录及其创建时间统计。评论删除或审核状态变化可能使历史互动数字变化，UI 必须说明这是当前有效互动，不把它混入不可变浏览日汇总。

### 5.3 回填、日结与清理

新增迁移只新增集合、字段与索引，不修改已应用迁移。迁移遵循项目 JSVM 限制，不使用原生数组方法。

1. 部署前备份 `pb_data`，提供 down 迁移与恢复步骤。
2. 从仍存在的原始事件回填每日总表和维度表，最早日期以 `source_min_day` 为准，不补造更早历史。
3. 每个日批次独立事务、按 key 覆盖写或 upsert；重复执行结果相同，不累加旧结果。
4. 每日任务先完成并核验前一自然日汇总，再清理同时满足以下条件的原始事件：`created < 今天 00:00 - 89 个自然日`，且该日 `<= last_finalized_day`。今天及其之前连续 89 天合计最多 90 天；即使清理延迟，可下钻查询也不得超过这个原始覆盖边界。
5. 失败时记录可诊断日志，保留尚未安全汇总的原始事件（即使已超过 90 天），不推进水位；下一任务可重试。超过边界仍未汇总的数据只能作为补账保护存在，UI 必须报告缺口，不能悄悄纳入下钻或删除。
6. 数据源按查询类别决定：无筛选的总量、趋势和单维度排行使用已日结 rollup，当天及水位后的日期使用 raw 并以 `coverage.partial` 标注；**任意两个及以上维度筛选、对象下钻或其关联维度查询一律完整使用 raw**，不得混用 raw 与 rollup 的结果。一次请求的每个聚合项只能有一个权威来源，不能拼接两套计数。
7. 用同一批 fixture 对总浏览、访客·日、各维度合计和随机日期做 raw / rollup 对账；`post + path` 等于总量，其他维度合计与总量差异只能来自空来源、未知地理等明确的未知桶。

汇总本身可由尚存的原始数据重算；超过原始保留期的汇总不允许无依据重造。

## 6. 统一分析接口

新增 `/api/analytics/overview`、`/api/analytics/drilldown`、`/api/analytics/export`，一个接口只承担一种职责。新页面统一使用它们，避免不同图表各自定义计算方式。旧 `/api/blog-stats` 在迁移期间保持兼容，公开 geo 响应先移除城市字段，再逐步收敛调用方。

### 6.1 请求契约

- `range`：`7d | 30d | 90d | 1y | all`，缺省 30d；非法值返回 400，不静默回落。
- `compare`：`previous` 或关闭；上一周期为紧邻当前起点的等长完整自然日区间。当前侧和上一周期都排除尚未结束的今天，两侧覆盖日数一致才给出比较。交叉筛选的 90 天窗口所需上周期已经超出 raw 保留边界，因此 `compare.available=false`，不提供伪环比；7 / 30 天的交叉筛选在原始覆盖完整时可比较。
- `filters`：可选 `postId`、`referrerOrigin`、`country`、`region`、`device`、`path`，服务端逐项白名单、规范化、长度限制与绑定参数查询。`path` 用于站内非文章页面详情，与 `postId` 互斥，冲突时返回 400。
- `dimension`：`post | path | referrer | country | region | device`，用于下钻，不能任意传表名或列名。
- `page`：从 1 开始的页码，默认 1，最大 10000；`limit` 默认 20、最大 100。按 `page_views` 降序和稳定 `value_key` 升序排序，服务端返回 `total / page / limit / totalPages`，越界页返回空 `items` 与同一分页元数据，不允许无界响应。导出独立使用有界聚合查询，不受展示页页码截断。

7 / 30 / 90 天为包含当天在内的连续自然日窗口；所有起止时间由 Asia/Shanghai 日界转 UTC 后查询。`from` 为窗口首日 00:00，`toExclusive` 为窗口结束次日 00:00，统一使用 `[from, toExclusive)`。今天是尚未日结的残日，指标卡单独标注。1y / all 只提供匿名汇总趋势和单维度排行，不提供对象下钻，能力代码为 `POLICY_LIMITED`；7 / 30 / 90 天内，交叉筛选或下钻如早于 raw 边界则返回 `CROSS_FILTER_REQUIRES_RAW`，不能把无数据或产品限制冒充服务失败。

所有 SQL 片段来自固定映射，值只用绑定参数。为常用查询增加 `(event, created)`、`(post_id, event, created)`、`(visitor_hash, path, created)` 等复合索引，分别覆盖窗口、文章下钻与同日同路径去重；实际索引以执行计划和 fixture 验证，不盲目添加重复索引。

### 6.2 响应契约

每个响应包含：

- `meta`：请求与生效范围、起止日、上一周期、时区、生成时间、数据新鲜度；
- `coverage`：raw / rollup、最早可覆盖日、是否支持完整下钻、缺失能力及原因；
- `metrics`：浏览量、访客·日、当前有效互动；`averageDaily` 为含今天的窗口日均，`completeDayAverage` 为排除今天的完整日日均，二者 UI 不可省略标注；`coveredDayAverage + coveredDays` 仅在历史覆盖不完整时作为“有记录期日均”展示，不能用于默认指标或环比；
- `compare`：只有两侧完整日覆盖一致才返回 `baseline / delta`，环比一律基于 `completeDayAverage`，不使用含今天的 `averageDaily` 或覆盖不足时的 `coveredDayAverage`；`todayPartial` 单独表示今天数据，不引入未经确认的小时同比。
- `series`：按日或按月桶、明确单位与零值补齐规则；
- `dimensions`：当前允许的排行与稳定 ID；
- `availability`：浏览、互动、地理各自可用性，不把局部失败混成整体空数据。互动在选定时间范围内按当前有效记录的 `created` 统计，仅补充其“截至查询时仍有效”的口径，不暗示被删除互动可恢复。

7 / 30 / 90 天趋势按日补零，1y 按月补桶；`all` 以首个有数据日起按月聚合。`source_min_day` 之前没有证据的日期不宣称“零访问”；请求窗口早于可核验数据的起点时，覆盖率显示 `partial`，平均值的 caption 明确标注为“有记录期日均”并列出实际覆盖日数，不能与完整窗口日均混淆。

鉴权采用端点矩阵，不复用只看 role 的 `stats_lib.isAdminRequest`：

| 端点 | 权限 |
| --- | --- |
| `/api/analytics/overview` | 匿名可读，但只有公开总量、国家级热度、已发布内容与 origin 级来源摘要；author 及以上可读取设备总分布，管理员字段仍按权限裁剪 |
| `/api/analytics/drilldown` | `admin / super_admin` 且 `requireAdminStepUp({ requireVerifiedEmail: true })`，region、设备交叉筛选和互动明细均适用 |
| `/api/analytics/export` | 同 drilldown，必须 step-up 验证，不接受仅凭 admin access token 的 role-only 认证 |

公开响应只含明确列出的聚合字段，不能通过 `detail=1` 改变权限。author 保留总览阅读权限，不能借缺少 detail 静默推断有管理员权限。无 step-up 的 admin token 请求 drilldown / export 必须 403。

## 7. 指标定义

| UI 名称 | 定义 | 不得声称 |
| --- | --- | --- |
| 近 N 天浏览量 | 范围内 pageview 事件数，默认包含 bot | 全站历史总访问、真实人类阅读 |
| 访客·日 | 每日 distinct visitor hash 之和；同日近似去重 | N 天独立访客人数 |
| 日均浏览 | 浏览量 / 定义窗口的自然日数，零访问日计入；今天残日单独说明；有记录期不足时列出实际覆盖日数 | 有访问日的平均值、把无历史当成零访问 |
| 当前有效互动 | 范围 `created` 内、`post_id` 非空的所有 reaction type，加上范围 `created` 内审核通过、未删除的评论；评论自身 reaction 另列，不计入文章互动 | 永久不变的历史事件数、所有类型反应的混合总数 |
| 文章累计阅读 | `posts.views`，同日同访客同路径去重的累计值 | 与 page_views 窗口浏览量等价 |
| 内容互动分（累计） | 独立卡片：累计 `posts.views + 文章 reactions*3 + 当前有效评论*5`，不随时间筛选变化，保留现有接口语义 | 窗口内互动分、文章质量或读者满意度 |

浏览量、访客·日及地理统计包含已识别的 bot；设备维度可查看 bot。除非另行实现并验证过滤口径，不展示“已去除爬虫”的数字。

## 8. 隐私、权限与导出

- 任何前端响应均不包含 visitor hash、IP、完整 UA 或原始访问记录。
- 公开接口不返回城市；从现有公开 geo region 响应移除城市字段。后台地区下钻仅返回管理员所需的聚合，不提供单访客轨迹。
- 公开国家热度中，`max(page_views, visitor_days) < 5` 的国家**完全不披露该国的浏览量、访客·日和地图色阶**，不设置可差分的“其他国家”数值；不足 5 的国家统一显示为“少量其他地区”，不设数字。达到阈值的国家才展示精确聚合，并在排行、地图与所有公开窗口使用同一规则；跨窗口重复请求、总量差分、公开 region 和筛选不能绕过这一限制。公开页不提供 CSV 导出。未知国家只显示存在未知样本，不伪造位置；管理员可在 step-up 权限内查看国家／地区聚合。公开页文案改为“按日匿名标识与聚合统计”，不再声称“不含任何个人信息”。
- 地理头采用硬信任约束：仅当 TCP peer 命中 `PB_TRUSTED_PROXY_IPS` 时采信 ESA 的 `ali-ip-country / ali-geo-*`，复用 `client_ip.js` 的可信代理解析；Caddy 对转发请求覆盖或删除客户端传入的这些头。不信任或无法验证时，地理状态为 unavailable，绝不标为可信。
- referrer 仅保留 origin；URL 查询与 fragment 不进入来源分析。
- 导出为当前筛选的 CSV 聚合，带时间范围、时区、筛选条件、生成时间和口径说明；不含原始标识或城市。
- CSV 转义逗号、引号与换行，并防止以 `= + - @` 等开头的单元格被表格软件当作公式执行。每次导出最多 10000 条聚合行，返回 `exportedRows / truncated`；达到上限时明确提示缩小范围或筛选，不生成无限文件，也不把页码当导出上限。
- 权限测试覆盖匿名、reader、author、admin、super_admin，以及伪造 detail / dimension / geo 参数；无 step-up 的 admin token 请求 drilldown / export 必须 403，伪造地理头不得改变国家归属。

## 9. 错误处理、性能与可验证性

### 9.1 模块级降级

- 浏览数据失败不影响互动模块；互动失败不清空浏览趋势。
- 无数据返回成功空集合；未配置、无权限、超出下钻窗口、服务失败各有明确状态。
- 每个失败模块可重试，成功模块不强制整页刷新。
- 切换筛选时取消或忽略过期请求，旧响应不得覆盖新条件。
- 图表与地图失败时仍保留数据表与重试。

### 9.2 性能预算

- 保留合理的短 TTL 服务端聚合缓存，缓存键包含完整范围、筛选、维度与权限上下文，避免公开／管理员串数据。
- 3D 和地图图形按需加载，首屏不等待 3D。
- 对范围筛选和 join 使用复合索引；通过 fixture 的执行计划与计时验证，不以“数据量小”跳过回归。
- 原始表保留窗口固定，长趋势与单维度排行走 rollup；不每次查询扫描全历史事件。非文章 path 每天最多 100 个，剩余进 `other`；后台查询一律分页，不允许任意 path 列表无界输出。
- 保持现有 `/stats` 的 CLS 防护目标，用条件一致的骨架和稳定图表容器，不引入自动布局跳动。

## 10. 验收与回滚

### 10.1 数据与权限

- 7 / 30 / 90 天真实范围一致；非法范围不静默改值。
- 跨零访问日、跨月、跨年和 Asia/Shanghai 日界 fixture 通过。
- 访客·日、日均、上一周期、文章与来源筛选的数学口径均有测试。
- rollup 回填和定时任务重复执行不增加数字；raw / rollup 对账通过。
- 原始事件 90 天清理不会在汇总失败时误删；日结失败产生 `missingDays`，不显示虚假零值。
- 单维度汇总与交叉 raw 查询各自对账；交叉筛选不读取 rollup；90 天交叉筛选明确无环比。
- 文章 relation 禁止级联删除；`post + path` 不双计，已下架文章和 path `other` 桶均通过 fixture。
- 匿名请求无城市、无 visitor hash、无原始轨迹；小样本国家在任意窗口、地图和差分请求中均无精确值；管理员 step-up 正向与反向均验证。

### 10.2 前端与集成

硬门禁：

`test:admin-auth` 按 `astro/package.json` 的实际脚本入口执行，不假设工作目录参数。涉及 PB hook 时，在本地 PB 应用新增迁移，运行 `scripts/test-stats-friend-local.ps1`、`scripts/test-api-surface-local.ps1` 及现有登录、评论集成测试；实施计划为这些 PowerShell 测试指定可运行的本地环境，不把未执行写成通过。涉及 compose 时运行 `docker compose config`。

### 10.3 回滚

- 前端与服务端 hook 用 `git revert` 回到上一稳定版本；旧入口保留至兼容期结束。
- 迁移提供 down；实际部署前备份 `pb_data`，异常时停止写入、恢复备份并重启 PocketBase。
- 已删除的过期原始事件只能由备份恢复；rollup 是可重算派生数据，不能替代原始备份。
- 新旧接口短暂并存，验证旧公开统计与友链排行不受新聚合影响后再移除重复页面逻辑。
