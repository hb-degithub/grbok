# 全站轻科幻「轨道日志」前端重构设计

日期：2026-11-19  
状态：总体设计已获用户确认，待用户复核本文档  
基线：`main` / `d2c4214`

本文取代 `2026-11-16-sci-fi-minimal-demo-design.md` 与 `2026-11-17-sci-fi-site-wide-design.md` 中的视觉方向、固定令牌字面值和旧类名约束；既有代码的行为、安全和数据契约仍然有效。本设计不是对已下线旧路由或旧实现的恢复要求。

## 1. 目标与范围

对胡巴的博客全部前端进行视觉与交互重构，建立统一的轻科幻「轨道日志」设计系统，并覆盖：

- 访客前台：首页、文章列表与详情、标签、归档、关于、项目、友链、相册、留言、统计、状态、订阅、`/help/mail-errors`、`/404`、`/offline`、`/blocked`、既有 demo 页及 `/feed.xml` 兼容。
- 认证与账号：登录、注册、找回/重置密码、邮箱验证、邮箱变更、通知设置。
- 管理后台：现有全部 21 个后台页面及其导航、列表、表单、监控、邮件、安全与配置界面。

保留全部已有页面、功能和 URL。优化导航分组、入口可见性和移动端操作路径，不借重构删除低频功能。

### 已确认的体验方向

- 全站视觉与交互升级，而不只是更换颜色。
- 轻科幻风格，明暗双主题，并保留已有主题模式能力。
- 首页与展示页更具沉浸感；文章阅读、认证和后台工作区克制高效。
- 重新设计现有特效，不沿用旧光标、启动层和欢迎层的视觉实现。
- 采用设计系统优先、分页面组实施的渐进方案，而非一次性整站重写。

## 2. 非目标与安全边界

本次不是后端重写、数据模型调整或权限策略变更：

- 不改变 PocketBase 集合、字段、API 请求/响应、服务端认证或权限规则。
- 不修改 `pb_hooks/**`、`pb_migrations/**`、`Caddyfile*`、部署与边缘安全配置。
- 不修改 `astro/src/lib/pocketbase.ts`、`security.ts` 及认证/step-up/TOTP 安全核心逻辑。
- 不改变 `AdminGuard` 的判定顺序、角色要求、邮箱验证和 step-up 安全语义。
- 不改变评论审核、邮箱验证、点赞/收藏、危险操作二次确认及 Service Worker 的 HTML/API 不缓存规则。
- 不通过放宽测试、删除失败用例或硬编码演示数据制造“通过”。固定旧色值/类名的视觉断言可因本设计有依据地替换，但必须保留或增强对应行为、可访问性与安全断言，不能仅删除。

视觉重构可能暴露或触发现状缺陷。涉及交互、数据可见性、状态语义的修复必须单独列出、先复现并补行为测试；不混入无法审查的大批量样式修改。

## 3. 现状与重构理由

子智能体已对前台、后台/认证、测试能力进行只读审计。当前代码以 Astro SSR、React islands、Tailwind CSS 4 和 Framer Motion 为主，已有 `--sf-*` 明暗色板与共享布局，但存在以下问题：

- 多组页面重复实现页头、面板、按钮、空态与分页，尺寸令牌未真正落地。
- 导航配置分散，部分已有页面缺少入口；登录与账号页使用不一致的外壳。
- 全站装饰岛较多，旧光标、启动/欢迎层影响内容与工作流，部分弹窗缺少焦点管理。
- 后台存在把加载失败显示成空数据、未保存编辑直接关闭、表格移动端可用性不足等问题。
- 现有部分测试锁死类名、令牌字面值或旧页面结构；视觉改动需要同步替换为行为与可访问性断言。

详细文件证据见实施计划；本设计不把未经运行时验证的审计推断当作已复现缺陷。

## 4. 视觉设计系统：「轨道日志」

### 4.1 视觉语言

将博客表达为持续运行的个人观测站：内容是主航道，轨道、坐标与状态光是辅助信息，而不是覆盖内容的 HUD。

- **浅色主题**：雾白画布、浅蓝灰层次、细腻金属边界与少量青蓝能量光。
- **暗色主题**：深空蓝黑、低亮度星尘与青色状态灯；避免纯黑、刺眼霓虹和高饱和大渐变。
- **排版**：以 Noto Sans SC 保证中文阅读，Geist/Geist Mono 用于拉丁文字与真实数据。增大关键标题层级、增加内容留白，限制长文行宽；减少重复的等宽大写装饰标签。
- **形状与层次**：小至中等圆角、薄边界、局部柔光和层次化表面。面板用于表达分组，不再为所有内容套同一种细线框。
- **语义色**：除主强调色外，为成功、警告、错误、信息定义明暗两套令牌，并验证对比度。
- **布局**：统一页面容器、 gutter、页头、内容区与工作区宽度；不同页面根据内容采用不同构图，避免全站同一模板。

最终令牌字面值在首个视觉样板中确定并记录，不在未渲染验证前锁死具体色值。为降低批量迁移风险，第一阶段保留 `--sf-*` 语义命名空间，更新其定义并补齐语义令牌；只有确需新增的概念才引入新名字，不并行维护两套色板。

### 4.2 新特效与动效

重新设计轨道线、光带、空间层次、数据脉冲和滚动场景：

- 首页/关于/项目/相册等展示页允许使用较明显的场景动效和滚动叙事。
- 文章列表/详情/标签/归档仅保留阅读辅助、状态与微交互。
- 认证/账号/后台不启用持续跟随或遮挡操作的装饰动效。
- 旧光标、启动层、欢迎层全部纳入重新设计与使用场景评审；不得在工作区或错误页无条件阻断内容。
- 优先 CSS/轻量 SVG/Framer Motion；仅在确有视觉价值且性能预算允许时使用 Canvas/WebGL。
- 字体使用现有自托管资源，不新增第三方字体 CDN。CSP/Worker/WASM/网络白名单保持不变；若所选效果需要修改这些策略，则改用不需要放宽策略的实现，不默认改 Caddyfile。
- 所有动效尊重 `prefers-reduced-motion`，页面隐藏时停止不必要的动画和轮询；无 JS 时正文、导航和错误状态仍可用。
- 不自动播放声音，不加入高频闪烁、持续晃动或影响输入的特效。

## 5. 信息架构与页面设计

### 5.1 共享导航与外壳

- 建立单一导航配置，供桌面导航、移动抽屉、页脚与账号入口使用。
- 按内容、互动、站点信息组织访客入口，补齐已有页面的移动端入口。
- 管理导航按内容、运营、系统与审计分组，显示真实用户角色，不将页面所需角色误写成当前用户角色。
- 保留公告、搜索、主题切换、反馈、跳转到正文及键盘操作。
- 保持 URL 不变；页面筛选、标签、分页等需要刷新保持的状态优先使用 URL，而非仅存在组件内存。

### 5.2 展示页

- **首页**：以新的不对称 Hero 和轻量空间场景建立品牌；保留最新文章、社区、作者、友链、状态与登录入口，减少重复区块和重复状态轮询。
- **关于/项目**：以经历、项目轨迹与技术能力组织内容，不为每张静态卡片建立独立 React 岛。
- **相册**：保留瀑布流与灯箱，重做浏览、筛选和键盘体验；图片加载与减少动效优先。
- **统计/状态**：用真实数据驱动轨道、波形或状态场景，不伪造实时数据；加载、错误、空数据明确区分。

### 5.3 阅读路径

- **文章列表/标签/归档**：强化标题、摘要、日期与标签层级；统一筛选、分页、空态和错误重试。首屏内容优先 SSR，保留分页与可分享状态。
- **文章详情**：正文宽度、中文行距、代码块、目录、阅读进度优先；互动和评论保持可见但不过度装饰。
- **评论/留言**：保留审核、邮箱验证、实时评论与回复能力；统一表单、状态反馈和屏幕阅读器播报。
- **错误/离线/订阅**：提供明确下一步，不显示装饰性遮挡，不将不可信查询参数渲染成安全提示。

### 5.4 认证与账号

- 统一登录、注册、找回/重置密码、验证、邮箱变更与账号设置的外壳和反馈组件。
- 登录方式使用语义正确的 tab/面板、键盘操作与清晰焦点。
- 将错误关联到正确字段；成功、处理中、可重试、令牌失效均有独立状态。
- 未登录账号页显示明确引导，不返回空白。
- 只调整呈现和交互编排；认证端点、角色跳转、限流、验证、TOTP 和恢复流程保持原契约。任何现有流程缺陷单独复现和修复。

### 5.5 管理后台

后台以清晰、高密度但易扫描的工作台为方向，不复制展示页的沉浸特效。

- 统一 `AdminLayout`、真实角色信息、移动侧栏、页面标题和面包屑。
- 建立共享 `PageHeader`、`Panel`、`Toolbar`、`Field`、`Badge`、`Table`、`Pagination`、`Dialog`、`EmptyState`、`ErrorState`、`Skeleton` 等基础组件。
- 列表支持明确筛选、分页、加载、空和错误状态；小屏采用合理列折叠或卡片布局，不只依赖横向滚动。
- 表单显示字段级错误，加载失败不得用默认值覆盖原配置；未保存修改关闭前必须确认。
- 危险操作沿用明确的二次确认；弹窗具备焦点陷阱、Esc、焦点归还及适当的背景隔离。
- 保留全部现有后台页面与权限入口，分批替换，不在一次提交中重写所有业务组件。

## 6. 前端结构与数据流

保持 Astro SSR + React islands + 现有服务层，不迁移框架或样式库。

```text
Astro 页面 / SSR 数据
  → BaseLayout / AuthLayout / AdminLayout
  → 共享设计令牌、布局与交互原语
  → 页面级组件和必要的 React islands
  → 既有 hooks / services / PocketBase API
```

- 将视觉令牌、排版、间距、表面和动效集中在设计系统层，避免页面各自定义。
- 共享组件保持单一职责和稳定 props，React 组件使用 `export default`。
- SSR 负责可读首屏和必要公开数据；客户端岛负责交互。避免为静态内容大量水合。
- 复用现有 service/hook 数据契约；同一页相同公开状态共享请求或缓存，避免重复轮询。
- 主题解析保留 `blog-theme-mode` 与现有事件兼容，集中实现，避免布局与导航各自维护。
- 前端 hooks 属于本次可调整的 UI 状态与请求编排层：可收敛轮询、页面隐藏暂停、错误/取消和共享状态，但不改变既有 service 签名、API 形状或认证安全语义；变更必须补对应行为测试。实施计划按具体 hook/组件划分所有权。
- 清理已确认无引用的特效与死代码；不清理仅有静态扫描推测、可能有运行时引用的资源。

## 7. 状态、反馈与错误处理

所有数据视图至少区分：

- 初次加载与后续刷新；
- 有数据；
- 真空状态；
- 可重试错误；
- 无权限、未登录或需进一步验证（如适用）。

错误不能伪装成空数据，也不能在设置页静默回退为可保存的默认值。异步反馈使用统一、带适当 live region 的 Toast 或内联状态；关键表单错误同时贴近对应字段。动效不是状态反馈的唯一载体。

## 8. 实施与委派策略

按下列阶段拆分，每阶段保持可审查、可验证、可回滚：

1. **基线与契约**：记录现状，运行基线验证；区分视觉测试与行为/安全契约，保留有效回归。
2. **设计系统与外壳**：建立新令牌、共享原语、主题、导航、反馈与响应式规则。
3. **首页与展示页**：完成新视觉样板及展示页场景，评审后再推广。
4. **阅读路径**：文章列表、详情、标签、归档、评论与相关互动。
5. **认证与账号**：统一外壳、表单、反馈和完整流程回归。
6. **后台工作台**：先共享外壳/控件，再按只读展示、CRUD、配置/邮件/安全等页面组完成全部 21 页。
7. **全站收尾**：导航完整性、性能、资源、SEO 兼容、视觉与可访问性验收。

由主智能体拆解、协调和验收；子智能体按不重叠范围承担前台、后台、测试和独立审查。共享基础组件先于依赖它的页面完成，避免并发修改同一文件。每批交付须报告实际修改、执行命令、结果与未验证范围。

设计文档确认后，再编写详细实施计划；不在本阶段直接批量修改页面。

## 9. 验证与验收

### 每批硬门禁

以下均为每批必须执行的实际命令，不允许因“只是样式”而跳过：

- `cd astro && npm run lint`
- `cd astro && npm run check`
- `cd astro && npm run build`
- `cd astro && npx vitest run`
- 涉及认证、账号或后台时：`cd astro && npm run test:admin-auth`；涉及 `admin-auth/` 服务时另执行 `cd admin-auth && npm test`。
- 按改动执行聚焦行为测试；新增 `astro/test/` 的 Node 测试必须显式登记到对应脚本，确保实际执行。

本地隔离构建使用 `ALLOW_LOCALHOST_SITE=1 npm run build`，不伪造生产地址；CI/生产构建使用既有正式 `PUBLIC_SITE_URL` 和 `PUBLIC_POCKETBASE_URL`。环境缺失是验收配置问题，不作为跳过构建的理由。

### 测试迁移规则

- 将旧视觉类名、固定色值、实现形状的断言改为用户可见行为、ARIA/键盘交互、数据状态和稳定的 `data-*` 钩子。
- 令牌字面值仅在首个视觉样板评审通过后一次性更新；之后断言令牌存在与文本/控件对比度，而非锁死 hex。
- 状态以可访问角色与 `data-state=loading|empty|error` 等语义判定，不能靠装饰性文案判断；空状态与错误必须可区分。
- 后台 SSR 无敏感数据、`noindex`、匿名跳转、step-up 不泄漏等安全用例完整保留；仅将脆弱 class 选择器替换为稳定语义钩子。
- 不为适应重构而删除真实失败或认证/权限断言；确已过时的测试须说明被哪项行为测试替代。

### 浏览器与视觉矩阵

- 桌面与移动、浅色与暗色，覆盖首页、代表性展示页、文章详情、认证页和后台工作页。
- 检查溢出、布局位移、首屏主题、水合、键盘导航、焦点、减少动效、无 JS 正文和空/错/加载状态。
- 用真实或有意义的测试数据覆盖文章、评论、搜索、相册、统计等，不以空 mock 证明完整功能。
- 扩展既有 `astro/e2e/sci-fi-site` 与 `npm run test:e2e:site`，不另起重复套件；先实测基线。使用其独立端口与 `reuseExistingServer=false`，如 4338 被占用则改配空闲测试端口，不连接或重启现有 4321/生产服务。
- 现有 `check:visual`/`check:mobile` 仅在显式 `--base-url` 指向本次隔离测试服务时使用，不采用默认的 4321。
- 验收由测试子智能体执行，主智能体核验退出码、截图/报告，失败即阻塞该批完成；不自动部署生产。
- 新增有意义的分页、长文、图片、评论、搜索与错误夹具；后台准备隔离的已登录角色/step-up 测试替身或种子 PB，不以匿名空 mock 代替后台业务验收，不连接真实账号。
- 至少覆盖 320、390、768、1024、1440 宽度及必要的横屏场景；现有 1440/390 × 明暗矩阵保留。
- 增加无预置本地存储的首屏主题用例、`reducedMotion` 用例，以及 SSR HTML 的 404/noindex/无敏感后台数据契约断言。
- 检查 `documentElement.scrollWidth <= innerWidth` 与目标容器无意外裁切；以实测布局稳定、无水合错误、无意外内容隐藏为判据。性能阶段先记录基线，后续逐阶段比较。
- 视觉截图作为评审证据保存到 `astro/test-results/` 的对应批次目录；首版基线须人工确认，后续像素基线/容差与更新流程在实施计划中明确，不能由实现者自行覆盖失败基线。
- 当前 Playwright 未接入 CI；每批以本地硬门禁验收。若后续将其接入 CI，须配置浏览器安装、版本锁定、报告上传和无 `continue-on-error` 的失败门禁，不假定现状已具备。

### 全站完成标准

- 所有现有 URL 与业务入口保留，导航可发现且移动端可用。
- 新视觉覆盖访客、认证和后台，展示页与工作区动效分级明确。
- 明暗主题、响应式、键盘与减少动效可用，无阻断性焦点或可读性回退。
- 数据/API/权限/安全契约不变，认证生命周期测试通过。
- 构建、单元/组件和关键浏览器验收通过；视觉测试不锁死无意义类名，安全红线不被弱化。

性能以首屏内容、减少无效水合/重复请求和稳定布局为目标；具体资源预算在基线测量后写入实施计划，不凭空承诺固定数值。

## 10. 文档漂移与后续维护
