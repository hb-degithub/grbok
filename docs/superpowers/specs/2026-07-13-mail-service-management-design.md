# 通用邮件服务与邮件管理中心设计

日期：2026-07-13  
状态：已确认，待实施  
适用版本：PocketBase 0.22.21、Astro 6、现有 Docker Compose 生产架构

## 1. 背景

博客已经具备注册验证、OTP 登录、评论通知等零散邮件代码，但当前状态不能作为完整邮件服务使用：

- 生产环境的 SMTP 环境变量不完整，PocketBase 启动日志显示自动配置被跳过。
- 现有验证邮件和评论邮件包含乱码及损坏的 HTML。
- 没有找回密码和重置密码页面。
- 评论审核通过、管理员回复、备份失败和服务异常没有完整通知链路。
- 自定义通知直接发送，失败后没有持久化重试、去重或后台可见状态。
- 配置名称绑定阿里云，不利于切换到其他标准 SMTP 服务商。

本设计把邮件能力拆成通用 SMTP 传输、账户事务邮件、可重试业务通知、宿主机告警和后台邮件管理五个边界。阿里云邮件推送是首个生产服务商，但业务代码不依赖阿里云专有 API。

## 2. 目标

1. 支持阿里云邮件推送，并兼容所有提供标准 SMTP 的服务商。
2. 完成注册验证、OTP、密码重置、邮箱变更四类账户邮件。
3. 完成新评论、评论审核通过、管理员回复三类业务通知。
4. 完成备份失败、容器异常、健康检查失败及恢复通知。
5. 提供仅 `super_admin` 可访问的邮件管理中心。
6. 为自定义通知提供持久化队列、去重、重试、取消和失败诊断。
7. 修复所有触达邮件链路的乱码和损坏模板。
8. 确保 SMTP 密钥只存在于服务器环境配置，不进入数据库、API、前端、日志或 Git。

## 3. 非目标

- 第一版不接入阿里云专属退信 Webhook、营销邮件、群发活动或用户画像。
- 第一版不实现多个 SMTP 服务商自动故障切换。
- 不新增常驻邮件微服务或消息中间件。
- 不允许管理员在后台输入、读取或导出 SMTP 密码。
- 不把验证码、令牌、完整邮件正文写入发送日志。

## 4. 方案选择

采用“PocketBase 系统邮件 + PocketBase Outbox + 宿主机独立告警”的混合方案。

- 账户邮件由 PocketBase 原生接口同步发送。请求方能立即获知请求是否被接受，令牌生命周期继续由 PocketBase 管理。
- 评论类通知先写入 Outbox，由 PocketBase 定时任务发送。业务保存不依赖 SMTP 可用性。
- 宿主机告警独立于 PocketBase。即使 PocketBase 容器退出，也能检测并尝试发信。
- 不新增常驻容器，避免给 1.8 GiB 内存服务器增加固定开销。

直接发送方案缺少可靠重试；独立邮件微服务在当前规模下增加了不必要的部署、鉴权和内存成本，因此不采用。

## 5. 配置模型

### 5.1 通用变量

生产使用以下通用环境变量：

| 变量 | 说明 |
| --- | --- |
| `SMTP_HOST` | SMTP 主机 |
| `SMTP_PORT` | SMTP 端口 |
| `SMTP_USERNAME` | SMTP 用户名 |
| `SMTP_PASSWORD` | SMTP 密码或专用凭证 |
| `SMTP_FROM_ADDRESS` | 已验证发件地址 |
| `SMTP_FROM_NAME` | 发件人名称 |
| `SMTP_TLS_MODE` | `implicit`、`starttls` 或 `auto` |
| `MAIL_ADMIN_RECIPIENTS` | 管理员通知地址，逗号分隔 |
| `MAIL_ALERT_RECIPIENTS` | 运维告警地址，逗号分隔 |
| `PUBLIC_SITE_URL` | 邮件链接使用的站点根地址 |

`SMTP_*` 是唯一对外文档化的主配置。为平滑迁移，配置解析器在通用变量缺失时读取现有的 `ALIYUN_SMTP_HOST`、`ALIYUN_SMTP_PORT`、`ALIYUN_SMTP_USER`、`ALIYUN_SMTP_PASSWORD`、`ALIYUN_FROM_EMAIL` 和 `ALIYUN_FROM_NAME`。

`SMTP_TLS_MODE=auto` 时，465 默认使用隐式 TLS，其他端口使用 STARTTLS。实施时必须用 PocketBase 0.22.21 的实际 SMTP 字段验证映射，不依赖新版本文档推断。

### 5.2 凭据边界

- 生产凭据保存在服务器 root 可读的共享环境文件，权限为 `0600`。
- PocketBase 仅通过容器环境读取凭据。
- 宿主机告警脚本读取同一份受保护配置，不在脚本中硬编码密码。
- 后台状态 API 只返回布尔状态、服务商标签、端口和 TLS 模式。用户名只允许局部脱敏，密码字段永不返回。
- 错误日志必须清除认证字符串、SMTP 用户名、完整收件地址、令牌和验证码。

## 6. 邮件类型与触发规则

### 6.1 账户事务邮件

| 类型 | 触发 | 发送方式 | 失败行为 |
| --- | --- | --- | --- |
| 注册验证 | reader 注册成功 | PocketBase 系统邮件 | 注册不回滚；页面允许限流重发 |
| OTP 登录 | 用户请求 OTP | PocketBase 系统邮件 | 返回通用失败提示并允许稍后重试 |
| 密码重置 | 用户提交邮箱 | PocketBase 系统邮件 | 始终显示相同成功提示，防止账号枚举 |
| 邮箱变更 | 已登录用户提交新地址 | PocketBase 系统邮件 | 保持原邮箱，直到令牌确认成功 |

四类邮件使用对应的 Mailer Hook 修改主题和正文，不再向全局 `settings.meta` 写入错误的模板字段。令牌只在渲染时进入邮件，不进入数据库或日志。

### 6.2 评论通知

| 类型 | 触发 | 收件人 | 去重与隐私规则 |
| --- | --- | --- | --- |
| 新评论 | 评论创建成功 | 文章作者和管理员列表 | 相同地址只发一次；评论者不通知自己 |
| 审核通过 | `pending` 变为 `approved` | 原评论者 | 只对首次状态转换发送 |
| 回复通知 | 回复首次变为 `approved` | 被回复评论的作者 | 回复者与收件人相同则跳过；未审核内容不外发 |

新评论通知失败不得阻塞评论保存。通知记录写入 Outbox 后即可结束业务请求。

### 6.3 运维告警

宿主机定时检查：

- 博客三个核心容器是否运行且健康。
- `https://hlydwz.com/api/health` 是否返回成功。
- 最近一次生产备份是否存在、是否超过允许时限。
- 磁盘使用率是否超过阈值。

同一故障只在状态首次变化时发送，持续故障按冷却时间提醒，恢复后发送一次恢复邮件。告警脚本保留 root 可读状态文件，避免定时任务重复轰炸。SMTP 本身不可用时只能写入系统日志，这是单传输通道的已知限制。

## 7. 数据模型

### 7.1 `mail_outbox`

一条记录只对应一个收件人，简化重试和抑制判断。

主要字段：

- `event_type`：通知类型。
- `template_key`：模板键。
- `recipient`、`recipient_name`：发送前所需地址和名称。
- `payload`：渲染所需的最小 JSON，不包含认证令牌或 SMTP 凭据。
- `status`：`pending`、`processing`、`retry`、`sent`、`failed`、`cancelled`。
- `attempts`、`max_attempts`、`next_attempt_at`。
- `dedupe_key`：事件、源记录、收件人哈希和状态转换组成的唯一键。
- `locked_at`、`locked_by`：防止并发重复发送。
- `last_error_code`、`last_error_summary`：脱敏错误。
- `sent_at`、`source_collection`、`source_id`。

创建只允许服务端 Hook。`super_admin` 可查看，通过受保护自定义路由执行重试或取消，不直接任意修改状态。已发送和取消记录保留 30 天，最终失败记录保留 90 天。

### 7.2 `mail_templates`

主要字段：

- `key`、`name`、`enabled`、`version`。
- `subject_template`。
- `content`：结构化 JSON，包括预标题、标题、段落、按钮文字和页脚。
- `updated_by`。

模板不保存任意脚本。渲染器只接受每种模板声明的变量白名单，并对所有动态内容进行上下文转义。链接协议只允许 `https:`，本地开发可允许 `http://localhost`。

### 7.3 `mail_rules`

每个事件类型一条规则：

- 是否启用。
- 是否通知文章作者、评论作者或管理员。
- 管理员收件人列表。
- 最大重试次数。

账户安全邮件不能通过普通通知开关关闭；只能通过 SMTP 配置状态决定是否可用。

### 7.4 `mail_suppressions`

主要字段：邮箱、原因、来源、启用状态、最后失败码和可选过期时间。管理员可手动添加或移除。只有明确的收件人永久错误才自动加入；SMTP 认证失败、连接失败和临时 4xx 错误不得抑制收件人。

### 7.5 `mail_delivery_logs`

保存所有账户邮件和通知邮件的最小审计信息：邮件类型、脱敏地址、地址哈希、结果、耗时、尝试次数、来源记录、错误分类和时间。不保存正文、payload、验证码或令牌。

## 8. Outbox 处理

PocketBase 定时任务每分钟处理到期记录：

1. 原子选取有限数量的 `pending` 或到期 `retry` 记录。
2. 写入处理锁；超过五分钟的陈旧锁可恢复。
3. 检查模板、通知规则和抑制名单。
4. 从模板与 payload 渲染 HTML 和纯文本版本。
5. 使用 `$app.newMailClient()` 发送。
6. 成功后清除敏感 payload，将状态设为 `sent` 并写发送日志。
7. 临时失败按 1 分钟、5 分钟、30 分钟、2 小时、12 小时退避，最多尝试 5 次。
8. 永久收件人错误直接失败并加入抑制名单；配置、认证或全局网络错误不得抑制地址。

所有触发器使用唯一 `dedupe_key`。Hook 被重复调用或管理员重复操作时，已有记录阻止重复入队。

## 9. 后台邮件管理中心

新增 `/admin/mail`，导航归入“系统”，要求 `super_admin`、已验证邮箱、有效 Passkey 验证会话和现有后台 IP 边界。

页面使用标签视图：

### 9.1 概览

- SMTP 已配置状态、服务商标签、端口和 TLS 模式。
- 24 小时发送量、成功率、待发送、重试中和最终失败。
- 最近失败摘要。
- 测试连接与测试发送命令。

### 9.2 发件队列

- 按类型、状态、脱敏收件人和时间筛选。
- 查看尝试次数、下次重试、错误分类和来源记录。
- 单条或批量重试、取消。
- 状态变化后保持表格尺寸稳定，不因动态内容跳动。

### 9.3 模板

- 编辑主题、预标题、标题、段落、按钮和页脚。
- 展示允许变量并插入变量。
- 隔离预览桌面和移动宽度。
- 测试发送、启停和恢复代码内置默认模板。

### 9.4 通知规则

- 启停评论类和运维类通知。
- 配置管理员收件人及作者通知策略。
- 校验、规范化并去重邮箱地址。

### 9.5 抑制名单

- 查看脱敏地址、原因、来源和时间。
- 手动添加、恢复或设置过期时间。

后台不得显示 SMTP 密码，不提供导出凭据或完整邮件正文功能。所有模板、规则、队列操作和测试发送写入现有审计日志。

## 10. 前台账户流程

新增：

- 登录页“忘记密码”入口。
- 密码重置请求表单。
- `/reset-password` 令牌确认页。
- 邮箱变更确认页或在登录状态下完成确认。

所有请求显示就地状态，不只使用弹窗。密码重置请求无论邮箱是否存在都显示相同文案。令牌错误、过期和成功状态必须可区分，但不得输出原始服务端错误或令牌。

## 11. 模板与内容规则

- 默认模板使用 UTF-8 中文，提供 HTML 与纯文本版本。
- 品牌名称、站点地址和发件人名称来自受控配置。
- 每个模板声明变量白名单；未知变量导致测试失败，不进行静默替换。
- 评论内容仅作为转义后的文本片段展示，并限制长度。
- 按钮之外提供可复制的纯链接。
- 邮件不加载第三方脚本，不嵌入跟踪像素。
- 触达文件中的现有乱码和损坏标签在同一实施中修复。

## 12. 安全与权限

- `mail_*` 集合默认无公开规则，只对 `super_admin` 开放必要读取。
- 所有邮件管理写操作通过服务端校验，并纳入后台二次认证会话检查。
- 测试发送限制为每个管理员 15 分钟 3 次。
- 收件地址在 UI 和日志中脱敏；服务端发送前才读取完整地址。
- 错误分类器禁止记录认证响应原文。
- Outbox payload 不允许认证令牌、密码、Cookie、Authorization 头或 SMTP 凭据。
- 模板预览放在隔离容器，不直接向管理页面注入模板 HTML。
- 邮件管理集合加入现有审计与 `require_verified_session` 保护范围。

## 13. 错误处理

- 账户邮件发送失败：接口返回安全、可操作的通用错误，服务端记录脱敏分类。
- 评论通知入队失败：评论本身保持成功，日志带明确告警标记，后台概览显示异常。
- 临时 SMTP 错误：自动重试。
- 永久收件人错误：停止重试并按规则抑制。
- 全局 SMTP 配置错误：暂停批次，避免把所有地址误判为失败；后台显示配置故障。
- 模板变量或渲染错误：该记录失败，不发送半成品邮件。
- 宿主机告警失败：写入 journald，下一周期在冷却规则内再次尝试。

## 14. 测试策略

### 14.1 自动测试

- 配置优先级与阿里云旧变量兼容测试。
- TLS 模式映射测试。
- 模板变量白名单、HTML 转义、纯文本生成和危险链接拒绝测试。
- 评论事件收件人、去重和状态转换测试。
- Outbox 锁、陈旧锁恢复、退避、最大尝试次数和错误分类测试。
- 抑制名单测试，确保认证失败不会误封收件人。
- 邮件管理路由权限、Passkey 会话、限流和审计测试。
- 密码重置的账号枚举防护测试。
- 所有 PocketBase Hook 语法检查和隔离运行检查。
- 全新数据库运行全部迁移并验证集合规则。
- Astro 构建、账户流程组件测试和移动端布局检查。

### 14.2 本地集成测试

本地 Compose 增加仅开发使用的 SMTP 捕获服务。测试注册验证、OTP、密码重置、邮箱变更、评论、审核、回复和运维告警八类模板，不向外部地址发信。

### 14.3 生产验收

生产启用前必须具备：阿里云 SMTP 专用凭据、已验证发件地址、管理员测试收件地址和可用域名。验收包括：

- SMTP 连接与测试邮件成功。
- 账户四类邮件至少各完成一次真实端到端验证。
- 评论三类通知完成入队、发送和去重验证。
- 人工制造一次临时失败，确认自动重试。
- 人工制造一个无效地址，确认永久失败分类且不泄露凭据。
- 停止非关键测试容器或使用测试探针，验证告警与恢复邮件。
- 后台邮件管理中心在桌面和移动端可用。
- 公网健康接口、登录、归档和管理入口策略无回归。

## 15. 部署与回滚

1. 备份 PocketBase 数据和当前 release。
2. 在隔离数据库运行新增迁移。
3. 部署代码但保持自定义通知规则关闭。
4. 配置 root 可读 SMTP 环境文件并重建 PocketBase 容器。
5. 运行测试连接和测试邮件。
6. 逐类启用账户邮件、评论通知和运维告警。
7. 完成生产验收后开启 Outbox 定时处理。

回滚时先停止 Outbox 定时任务，保留队列记录，切回旧 release。新增集合不在紧急回滚中删除，防止丢失诊断数据；后续确认不再需要时再通过独立迁移清理。

## 16. 验收标准

- 阿里云 SMTP 生产发信成功，切换其他标准 SMTP 仅需修改配置。
- 四类账户邮件、三类评论通知和运维告警均有可验证的端到端结果。
- 找回密码和重置密码流程完整且不泄露账号存在性。
- 自定义通知失败不会阻塞评论业务，且按策略重试和去重。
- 邮件管理中心可查看状态、管理模板与规则、重试或取消队列、管理抑制名单和发送测试邮件。
- 只有满足后台全部安全边界的 `super_admin` 能执行邮件管理操作。
- SMTP 密码未出现在数据库、API、前端构建产物、Git 和日志中。
- 邮件内容无乱码、无损坏 HTML，移动端和纯文本客户端可读。
- 自动测试、迁移预检、构建、生产健康检查和真实测试邮件全部通过。
