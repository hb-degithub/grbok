## 二、升级风险评估

### 🔴 高风险升级（需要仔细测试）

1. **Astro 6 → 7**
   - 可能包含破坏性变更
   - 需要检查所有 `.astro` 文件
   - 需要更新配置文件
   - 需要测试所有页面

2. **@astrojs/node 8 → 11**
   - SSR适配器重大更新
   - 可能改变构建输出结构
   - 需要更新Caddy配置

3. **PocketBase 0.22 → 0.27**
   - 跨5个次版本
   - 可能有API变更
   - 需要检查所有PocketBase调用
   - 需要更新hooks代码

### 🟡 中风险升级（需要测试）

4. **framer-motion 12 → 13**
   - 主版本升级
   - 可能有动画API变更
   - 需要测试所有动画组件

5. **ECharts 5 → 6**
   - 主版本升级
   - 可能有配置变更
   - 需要测试统计图表

6. **TypeScript 6 → 7**
   - 主版本升级
   - 可能有新的类型错误
   - 需要修复类型问题

7. **ESLint 9 → 10**
   - 主版本升级
   - 可能有新的lint规则
   - 需要更新配置文件

### 🟢 低风险升级（可以直接升级）

- React 生态系统（补丁升级）
- Tailwind CSS（补丁升级）
- 字体包（次版本升级）
- 其他工具库（补丁升级）

## 三、升级策略建议

### 方案A：一次性升级（不推荐）

**优点**：一次性完成所有升级  
**缺点**：风险高，难以定位问题  
**适用**：不推荐用于生产环境

### 方案B：分阶段升级（推荐）

**阶段1：低风险升级**（1-2小时）
```bash
npm update react react-dom @types/react @types/react-dom
npm update tailwindcss @tailwindcss/vite
npm update @fontsource/geist-mono @fontsource/geist-sans @fontsource/noto-sans-sc
npm update dompurify katex postprocessing jsrepo
npm update @astrojs/react @astrojs/rss @astrojs/check
```

**阶段2：中风险升级**（2-4小时）
```bash
npm install framer-motion@latest
npm install echarts@latest
npm install typescript@latest
npm install eslint@latest typescript-eslint@latest
npm update three mermaid
```

**阶段3：高风险升级**（4-8小时）
```bash
npm install astro@latest @astrojs/node@latest @astrojs/mdx@latest
npm install pocketbase@latest
```

**每个阶段后**：
1. 运行 `npm run build` 验证构建
2. 运行 `npm run test` 验证测试
3. 运行 `npm run check` 验证类型
4. 本地测试所有功能
5. 提交代码并部署

### 方案C：最小升级（最稳妥）

**只升级必要的包**：
```bash
# 只为了支持SSR
npm install astro@^7.2.1 @astrojs/node@^11.1.1 @astrojs/mdx@^7.0.5

# 其他包保持不变
```

**优点**：风险最小，快速实现SSR  
**缺点**：无法享受其他包的新特性和修复

## 五、推荐方案

**我推荐方案C：最小升级**

**理由**：
1. 目标是实现SSR，只需要升级Astro生态系统
2. 其他包当前版本稳定，无需冒险升级
3. 工作量小，风险低，快速实现目标
4. 后续可以逐步升级其他包

**具体步骤**：
1. 备份当前代码
2. 升级 Astro 生态系统（astro, @astrojs/node, @astrojs/mdx）
3. 修改配置文件启用SSR
4. 修改动态页面为SSR模式
5. 本地测试
6. 部署到生产环境
7. 验证功能
